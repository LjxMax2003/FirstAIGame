> **历史记录（2026-10-30 对账）**：本文与同目录的 `NUM_DESIGN.md` / `params.json` 同为 **v3.1 存档**，描述的是 6 武器 / 7 被动 / 3 进化的旧框架。现行数值以 `GameDemo/first-xi-xue-gui/scripts/*DB.gd` 为唯一真值，由 `tools/BalanceAudit` 守门；设计意图见 `docs/design/skills-balance-v6.md`，落地决策见 `docs/design/v7-completion-and-release-plan.md`。下文未改写。

## 做了什么

依据两份玩法文档建立**可复算的数值体系**，用项目里 34 个 SVG 的实测几何反查这些数（v3.0），本轮（v3.1）**为每个冲突给出可执行方案 + 全量替换武器命名**。

## 核心方法

**双侧平衡口径**：供给侧 = 武器 DPS 期望（基础 × 被动乘区 × AoE 几何命中）；需求侧 = 刷怪率 × 敌人血量；比值 `R(t)` 作节奏诊断器，要求单峰。

## 六条冲突方案（§10）

| 冲突 | 方案 | 改数值吗 |
|---|---|---|
| **光环视觉 r=124.8 vs 逻辑 160.65** | 贴图**放大 ×1.2873**（绘制 331.7px，环直径 321px，屏宽余 199px）。S2 逻辑收缩会让有效 DPS 192→116、峰值 0.71→0.64，代价太大 | 否 |
| **敌人画布留白，视觉是碰撞 2 倍** | `draw_scale = 2·contact_r / canvas_w`：杂兵 **0.500**（24px）、袋兵 0.583、精英 0.625、Boss 0.850 | 是（`contact_r` 变小） |
| **快速兵只换色，无法识别** | 拖尾 + 亮青描边。**不改速度**（速度 1.7 是需求侧的一部分）。灰度下 #EAF2FF/#B8F6FF 亮度 0.86/0.90 几乎相同，必须加轮廓 | 否 |
| **宝石面积 1.62 倍 vs 经验 12 倍** | 橙色宝石 `scale=1.6` + 脉动光晕，不改经验值 | 否 |
| **血条 4 等分 + 6 点伤害看不见** | `+20/级` 恰好全整除（25/30/35/40/45/50），保留；另加**双层缓动 + 受击闪光** | 否 |
| **炸弹每 3 分钟一次清屏** | Boss 战不掉 + 每局上限 4，超出转 1 颗橙色宝石 | 是（加约束） |

**6 条里有 4 条完全不碰数值。** 美术校核的价值不是"图错了就改数"，而是先分清哪些是图的问题、哪些是数的问题。

## 一个被验算推翻的补偿方案

原以为碰撞半径 24→12 会让威胁下降，需要把 `contact_damage` 6→7 补回来。实算包围圈（`R = n·r/π`，`gap = R−14−r`）：8 只敌人间距从 23.1px 收窄到 **4.6px**，6 只直接重叠（−3.1px）。**威胁没降，反而更贴身，所以不需要补偿。** 这条已从方案里撤掉。
