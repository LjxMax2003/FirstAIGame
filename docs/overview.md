## 四个关键设计决定

**Meta 只"乘"不"加"，且自成第二乘区。**
`最终值 = Stats.value_at(key, lv) × MetaSave.mult(key)`。这样 Meta 撑不破局内的 5 级上限，也不会把某件被动变成必选——它抬高的是所有构筑的基线。`params.json` 给了硬上限：Meta 满级总乘数 1.15 × 1.176 = **1.35**，必须远低于单武器进化的 **2.4**，否则"刷金币"会盖过"局内 Build"这个主玩法。测试直接断言了这条上限。

**`params.json` 的 `might` 改名成 `damage`。**
params 里 Meta 这条线的 id 是 `might`（攻击 +3%），但局内管线里的 `might` 是"受到接触伤害 −7%"的**减伤**。同名不同义，照抄 id 迟早出事，所以改叫 `damage`。

**商店只从结算界面进，不放暂停菜单。**
Meta 加成在 `Game._ready` 算进 stats，中途买的东西本局不生效。若暂停菜单也能开店，玩家会买到"攻击 +15%"然后这一局毫无变化——这是 meta 系统最常见的信任崩塌点。

**复活的无敌是 3 秒，不是 0.5 秒。**
复活点必然在怪堆正中。照搬普通受击无敌（0.5s）会让玩家刚站起来就被同一个人再撞死一次，2500 金币等于扔进水里。

## 顺手治了两个"陈年"假失败

都不是产品 bug，是**测量方法错了**，被本轮改动放大后暴露：

1. **同屏密度断言会飘（73~165）。** 同屏数 = 刷怪率 − 击杀率，而击杀率取决于自动选卡抽到了什么——等于让断言赌抽卡运气。`seed()` 也救不了：`randf` 调用次数受帧时序影响，同一颗种子两次跑仍得到 164 / 111。修法是先把构筑钉死（`_pin_probe_build`）再测，修复后稳定 146~165。
2. **升级弹窗抢暂停锁 → "恢复游戏"假失败。** 升级优先级高于暂停菜单（设计正确），但只要任何用例在等待期间恰好攒够经验，整树就暂停。修法是 `_prep()` 统一冻结经验条，要测升级本身的 Step 5 显式自己掌控时机。这一条消掉的是一整类 flake。

## 经济节奏：实测，不是估算

新增 `tools/EconomyProbe.tscn`（积分 `WaveTable` 刷怪表 + 直接调 `Game.coin_reward()` + 直接读 `MetaSave.TRACKS`），把"全满要几局"从手算变成可复现：

| 击杀比例 | 胜局金币 | 全表买满（49,250） |
|---|---|---|
| 0.42 新手 | 4,575 | 10.8 局 |
| 0.62 模型均值 | 6,555 | **7.5 局** |
| 0.74 熟练 | 7,747 | 6.4 局 |

**钩子在第一次死亡就成立**：哪怕只活 5 分钟（190 金币），也够买生命 Lv1 + 磁力 Lv1。

顺带查清一个口径冲突：`params.json` 写 `coins_per_kill = 0.05`，而 Step 11 实装的是 0.12。并排一算——0.05 会拖到 **14 局**买满（比 `reach_run = 10` 慢 40%），实装 0.12 是 7.5 局（快 25%）。**实装的反而更接近设计目标，所以决定不改**，并在工具里把这段对照常驻打印，免得下次再推一遍。

## ⚠️ 没做到的（如实记录）

1. **"买完明显变强"的体感未验证。** 数值上确实更强（有 55 项断言），但单线满级只 +15%，是 `params.json` 为"不盖过局内 Build"主动压低的。15% 在操作上手感是否够"明显"，**必须真人试玩才能回答**。
2. **经济节奏"算准了，但没玩准"。** §3 的数字来自刷怪积分 + 真实结算函数；但里面的击杀比例 R 仍取自数值模型（0.42~0.74），真人落在哪一档只能靠试玩。
3. **复活在 Boss 战中的体验未验证。** 只给 3 秒无敌、不清场，"复活即被围"的观感可能很差。
4. **Stage 3 遗留的三项仍未解决**：真人完整试玩、同屏 300~500、Windows `.exe` 导出（缺 4.7.2 导出模板，非代码问题）。
