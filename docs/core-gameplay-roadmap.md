## 阶段一：最小可玩回路（核心循环前四拍）

### Step 1 — 移动与相机
- 玩家唯一输入 = 移动（WASD / 方向键 / 单指拖拽）；相机平滑跟随。
- 大平面地图，无边界（无限地面）。
- ✅ 验收：角色流畅移动，屏幕始终居中。
- 📦 工程对应：`scripts/Player.gd`、`scenes/Game.tscn`（Camera2D）。

### Step 2 — 敌人生成与追踪
- 对象池复用敌人节点；AI = 直线追踪玩家 + 轻量分离（防重叠）。
- 屏幕外圆环刷怪；同屏 300~500 只不掉帧。
- 伤害走"距离判定"，不用物理引擎重叠检测（移动端性能关键）。
- ✅ 验收：大量敌人持续逼近，帧率稳定（HUD 有 FPS 显示）。
- 📦 工程对应：`scripts/EnemyPool.gd`、`scenes/Enemy.tscn`。

### Step 3 — 自动攻击武器（首版 3 把）
- 鞭子：面向交替的矩形横扫（近身范围伤害）。
- 蒜环：以玩家为中心的周期脉冲领域。
- 魔杖：朝最近敌人发射直线弹（穿透 1 次）。
- 武器只吃参数（冷却/伤害/数量/范围），零玩家按键。
- ✅ 验收：站着不动也能杀怪；走位改变命中密度。
- 📦 工程对应：`scripts/WeaponManager.gd`。

### Step 4 — 经验宝石与吸附拾取
- 敌人死亡掉蓝色菱形宝石，静止在地面。
- 进入磁吸半径后向玩家加速飞行；贴身自动拾取。
- ✅ 验收：拾取手感"贴脸吸进来"。
- 📦 工程对应：`scripts/GemPool.gd`、`scenes/Gem.tscn`。

### Step 5 — 升级三选一
- 经验曲线前密后疏：`next = 5 + level²`，前期 10~30 秒一级。
- 升级 → 全树暂停 → 弹出 3 张随机卡（新武器 / 武器升级 / 属性被动）。
- 武器上限 6 槽（首版先限制新武器数量）。
- ✅ 验收：走位→杀怪→捡宝石→升级闭环跑通 = **最小可玩版**。
- 📦 工程对应：`scripts/UpgradeDB.gd`、`scripts/ui/LevelUpUI.gd`。

## 阶段二：Build 系统（上瘾引擎）

### Step 6 — 被动道具与统一数值管线
- 被动不直接改武器，而是修改全局属性字典（`GameManager.stats`），武器从中读取：
  `damage / cooldown / area / speed / magnet / might / max_hp`。
- ✅ 验收：同一武器在不同被动下表现明显不同。
- 📦 现状：Step 5 的属性卡已走此管线，阶段二只需扩展卡池。

### Step 7 — 数据驱动武器定义
- 每武器 8 级成长曲线抽成配置（JSON 或 const 表），新增武器只加数据。
- 扩展武器类型：环绕类（圣经）、弹射类（飞刀）、抛射类（斧头）。
- ✅ 验收：纯配置新增第 4、5 把武器。

### Step 8 — 进化配方（首版 2~3 条）
- 精英怪（大色块、高血量）死亡掉宝箱。
- 配方 = 指定武器满级(Lv8) + 指定被动在场 → 开宝箱 → 进化终极形态。
- ✅ 验收：复现"可预期的惊喜"。

## 阶段三：压力曲线与单局节奏

### Step 9 — 时间驱动波次脚本
- 时间线事件表：0~5min 杂兵 → 5~10min 密度爬升 → 10min+ 精英+大波 → 25min+ 清屏怪。
- 血量/数量随时间指数增长（首版用连续插值，后改分段脚本）。
- ✅ 验收：30 分钟一局，能感知"前期割草→后期擦边求生"。
- 📦 现状：`Game.gd` 已有 RAMP 难度插值，阶段三替换为事件表。

### Step 10 — 场景资源点
- 可破坏物（墓碑/树）掉金币、火盆（范围爆炸）。
- 随机掉落：烤鸡回血、吸铁石全图吸宝石、炸弹清屏。
- ✅ 验收：走位路线因资源点产生策略选择。

### Step 11 — 死亡/胜利结算
- 存活 30 分钟判胜利；死亡/胜利结算金币、时长、击杀数。
- ✅ 验收：单局循环闭合。
- 📦 现状：首版已有简化结算（`DeathUI`），阶段三补金币结算。

## 阶段四：局外循环（留存）

### Step 12 — 金币 Meta 商店
- 局内击杀掉金币 → 结算入存档 → 商店买永久属性（攻击/血量/冷却/磁力/复活）。
- 存档持久化（user://save.json）。
- ✅ 验收：买完 Power Up 明显变强，形成"再来一局"钩子。
- 📦 工程对应：`scripts/MetaSave.gd`（存档 + 五条成长线，autoload）、`scripts/ui/ShopUI.gd`、
  `Stats.effective_at()`（局内被动 × 局外乘数，第二乘区）、`Game._finish()`（唯一入账点）、
  `Game._try_revive()`（复活）。
- ✅ 已完成（2026-10-27）：结算入账 / 原子写盘 / 商店五种状态 / 复活 3 秒无敌 / 跨局持久，
  自动化 55 项验收见 `docs/STAGE4.md`。

## 关键取舍

1. **首版砍掉**：多角色、多地图、进化、Meta 商店——先验证 Step 1→5 回路手感。
2. **精力压在两处**：Step 2 性能（对象池 + 距离判定）与 Step 8~9 节奏手感，这是上瘾机制的两个支点。
3. **移动端前提**：竖屏 720×1280 基准、单指相对拖拽移动、碰撞全部走距离判定不走物理引擎。

## 工程约定（Godot 4.7.2）

- **禁用 `:=` 推断 Variant**：凡取自 `Dictionary`（如 `stats["hp"]`、`owned["whip"]`）、`get_meta()`、无类型函数返回值的中间变量，一律写 `var x: T = ...` 或用 `float()/String()/int()` 包裹。否则 4.7 解析器报 `Cannot infer the type ... because the value doesn't have a set type`，并连带让引用同一 `class_name` 的所有脚本一起 Parse error。
- 聚合数据（子弹、特效）用带类型的内部 `class`，不用 `Dictionary` 手搓。
- 跨节点引用用 `@onready var _pool: EnemyPool = get_parent() as EnemyPool`，不要反复 `get_parent().xxx`。
- 数值统一走 `GameManager.stats`（全局属性字典），武器只读不算——这是 Step 6 的接口，提前定型。
- **autoload 脚本不要写 `class_name`**：4.7 会报 `Class "X" hides an autoload singleton`。
- 不用全局信号总线：敌人 `died(pos)` → `EnemyPool.enemy_died(pos)` → `Game` 监听，逐层显式连接，避免"信号声明但从未使用"警告。
