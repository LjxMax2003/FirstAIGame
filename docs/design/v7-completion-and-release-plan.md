# 《守艺人·百工夜行》v7 收尾与发布策划案

> 版本：v7 草案（2026-10-30）
> 依据：实读 `GameDemo/first-xi-xue-gui` 代码与数据表、`docs/` 全部设计文档、reports/EXECUTION_LOG.md（原根目录 10 月 27–29 日执行报告已压缩）；2026-10-30 实跑回归。
> 定位：**下一阶段的产品化策划**。不新增武器、不重做局内数值模型，只回答三件事：现在是什么、还缺什么、下一轮先做什么。

## 0. 一页结论

**项目已经跨过"能不能做出来"，停在"能不能交给玩家"的门口。**

局内循环是完整且可验证的：9 把武器、6 槽位、6 条进化、9 条被动、5 条局外成长、3 档真 Boss + 3 只小 Boss、30 分钟波次、浆壳 / 更鼓 / 潮涌、主动技震吼、金币商店、开始界面、16 个 shader。回归基线 **SmokeTest 312 条、V5InGame 148 条，今日实跑全绿**。

但"产品壳"基本是空的：**没有任何音频、没有新手引导、没有设置、没有回主菜单、没有可分发的构建、没有真人试玩、文化合规未启动**。同时存在一处必须优先处理的口径风险：**v6 平衡补丁只落地了视觉层，数值层从未落地，而当前代码又与 v5 / v6 两版模型都不一致**。

下一步只做三件事，按顺序：

1. **把数值真相源重新钉死**（代码回填模型 + 加一条回归审计），再决定 v6 的哪些数要落地。
2. **补产品壳**：音频最小集、设置与回主菜单、首局引导、Windows / Android 构建。
3. **补内容纵深**：角色选择（现成 5 张立绘）、敌人行走帧（现成素材）、摊位置景、图鉴；面具架后置。

不建议现在做：第 10 把武器、联机、任意时刻的局内存档、12 面面具、每日挑战。

## 2. 体验诊断：玩家旅程的九个断点

| # | 阶段 | 现状 | 断点 | 设计回应 |
|---|---|---|---|---|
| 1 | 首次启动 | 直接进主菜单 | 没有开场、没有"这是什么游戏"的一句话 | 3 页开场（`intro_01~03` 已有），可跳过 |
| 2 | 主菜单 | 新游戏 / 载入存档 / 商店 / 退出 | 无设置、无音量、无制作名单；"载入存档"语义模糊 | 改名为"传承已带入"或加副标题；补设置 |

### 3.2 P0：不做就不能对外

#### L-01 平衡真相源三漂移（最高优先级）

**证据**：

| 项 | v5 文档 | v6 文档 | 当前代码 |
|---|---|---|---|
| 花灯 `damage / dmg_per_level` | 3.60 / 0.65 | 2.50 / 0.45 | **4.00 / 0.80** |
| 皮影 `damage / dmg_per_level` | 11.0 / 1.30 | 8.0 / 0.90 | **8.00 / 0.80** |
| 打铁花 | 13 / 2.0，引爆 76 @0.65 | 9 / 1.0，铁水散开 150 @0.40 | **16 / 2.0，引爆 76 @0.65** |
| 回春 | `+1.5/s × lv` | `+0.6/s × lv` | **`+1.5/s × lv`** |
| 结界 | 每 12s，30+15×lv，刷新 | 每 8s，5+3×lv，池上限 30+6×lv，叠加 | **每 12s，30+15×lv，刷新** |
| `params.json` | v3.1，6 武器 | 未更新 | 9 武器、`damage` 线、金币 0.12 |

**影响**：v6 策划案 §3–§5 的四项解法里，只有 ④ 觉醒的**视觉层**落地；① 武器分层、② 铁水机制、③ 生存被动全部悬空。更麻烦的是代码里的花灯比 v5 文档还高（4.0 vs 3.6），"零操作最强"的问题可能比 v6 诊断时更严重。**任何后续调数都会踩在这个不确定上。**

**建议**：

1. 新建 `docs/balance/v7_model.py`，**以当前代码值为输入**回填，跑出真实的 band / R 曲线 / Boss 击杀，输出 `v7_result.json`。先回答"现在到底强不强"，再谈改不改。
2. 新增 `tools/BalanceAudit.tscn`：读 `WeaponDB` / `Stats` 的实际常量，与 `v7_result.json` 比对，差异 > ±3% 即红。把"文档漂移"变成回归能抓的失败。
3. 分两步落地，不要一次全改：
   - **第一步（纯数值 / 公式）**：v6 的 ① 花灯 / 皮影下调、③ 回春涓流 + 结界累积盾。改动集中在 `WeaponDB` / `Stats` / `UpgradeDB` 文案，风险低、可回滚。
   - **第二步（机制）**：v6 的 ② 铁水散开单列一轮。它要改 `fire_extinguisher` 的判定与 `explode_*` 字段，还会牵动 v6 已接的火星特效，必须单独回归。
4. v6 §6 里未机制化的两项（糖画"糖渍减速"、皮影 Lv8 +1 环绕）明确二选一：**要么排进 M2，要么在文档里标"已废止"**，不能继续挂着。
5. `params.json` 标 `deprecated`，或按 v7 重建；`NUM_DESIGN.md` 顶部加"v3.1 仅存档，现行口径见 v5/v6/v7"。

**验收**：`BalanceAudit` 绿；v7 band 跨度 ≤1.6× 且辅助档最低；打铁花单体 Lv8 <20；5 种极限构筑 Boss 击杀 ≤12s；`SmokeTest` 不低于 312。

#### L-02 音频从 0 到 1

**证据**：全工程 0 个 `AudioStreamPlayer`；`P5` 报告把音频列为 P6 可选，不阻塞首版。

**影响**：这是玩家最先感知的"完成度"。没有音频，再好的打击特效也像在打空气；手机端尤其明显。

**建议（最小集，不做动态混音）**：

- 总线：`Master → BGM / SFX / UI`；BGM -8dB、SFX -6dB、UI -10dB。
- BGM 3 段：0–10min 夜市、10–25min 压迫、25–30min 终局；交叉淡入 1.5s；潮涌时叠一层鼓点，不换曲。
- SFX 首批 12 条：9 把武器出手各 1、命中 1、受伤 1、拾取 1；随后补升级、Boss 吼、更鼓、胜利 / 失败、按钮。
- **红线**：命中音不能"一敌一音"。同屏 200 只时必然爆音，必须复用火花那套 30/s 令牌桶（`Game.SPARK_RATE`），同一音效最多 3 个并发，音高 ±5% 变体。Boss 吼 / 更鼓 / 进化不受节流。
- 移动端：OGG、48kHz、单声道；暂停时 BGM 低通 + 降 6dB，不要直接停。
- 首次播放预热：在主菜单 `_ready` 把所有 SFX 空放一帧，避免第一次打击时编译卡顿。

**验收**：峰值 < -1dBFS 无削波；首次播放无 >5ms 卡顿；静音状态下 `SmokeTest` 仍全绿。

#### L-03 真人试玩与手感验证

**证据**：`overview.md` 自述"买完明显变强"未验证；`P5` 的"5~8 人说出 3 门手艺 ≥80%"仍是人工项；难度曲线全部来自模型。

**影响**：所有数值结论都是模型结论。模型能证明结构不崩，不能证明好玩。

**建议**：M1 结束时做第一轮 5 人试玩，只测四件事：能否活过 10 分钟、是否理解三选一、是否被浆壳卡住、死亡后是否想再来一局。M2 结束做第二轮 10 人，补题材记忆与 Meta 体感。指标见 §5.4。

#### L-04 文化合规未启动（对外称"非遗"的硬阻塞）

**证据**：`P5` 出口 6 项中"文化顾问签字"标为 P0 阻塞；`compliance.md` 自述"待核"；名录、顾问、商标检索全未启动。

**建议**：AI 先产出 `docs/COMPLIANCE_CHECKLIST.md`（逐项：名录编号、图样来源、传承人授权、商标、AI 生成声明、宣传用语），交顾问对照代码与素材。**在签字前，所有对外物料不写"非遗"二字，改称"民俗手艺题材"。**

#### L-05 没有可分发的构建

**证据**：`build/` 为空；本机 `export_templates` 目录不存在；`export_presets.cfg` 只有 Windows。

**建议**：下载 4.7.2 导出模板；先出 Windows exe（内部试玩用），再出 Android APK（真机性能与触控）。构建脚本化，版本号写进标题与存档。

### 3.3 P1：影响体验完整度

#### L-06 流程与设置缺口

**证据**：`PauseUI` 只有"继续 / 重开"；`DeathUI` 的"退出"是 `get_tree().quit()`；主菜单无设置。

**建议**：

- 暂停菜单：继续 / 设置 / 重开 / 回主菜单（二次确认"放弃本局"）。
- 设置项：BGM、SFX、震屏开关、特效档位（完整 / 低配）、清除存档（二次确认）。写入 `user://settings.cfg`。
- 结算界面：重开 / 百工谱 / 回主菜单；"退出"不再杀进程。
- 死因归纳：被围 / Boss / 潮涌 / 其他，显示在结算第二行。

#### L-07 新手引导与开场

**证据**：`intro_01~03.svg`、`ui_wood_sign.svg` 已在库且未被任何脚本 / 场景引用；局内没有任何提示系统。

**建议**：3 页开场（可跳过，仅首局）+ 5 条情境提示（只出现一次，存 `MetaSave`）：

1. 首次触摸 / 按键："拖拽移动，出手是自动的。"
2. 首个灯花："灯花是经验，靠近会自动拾取。"
3. 首次升级："三选一，决定这一夜的构筑。"
4. 首次血量 <50%："震吼：冲刺 + 清开一圈，25 秒一次。"
5. 首个宝箱："满级武器 + 对应被动 = 进化。"

提示用木牌样式贴在 HUD 下缘，不暂停（升级卡除外），4 秒自动消失。设置里可重看。

#### L-08 文档口径回填

**证据**：`README.md`、`docs/overview.md`、`NUM_DESIGN.md`、`params.json`、`design.md` 均停留在 v3.1 / 阶段四口径。

#### L-09 终局 Boss 识别度

### 9.12 打铁花锁定（2026-10-31 缺陷修复，非计划内）

**现象**：两发铁水团永远背靠背 180°，且方向和场上敌人完全无关。

**根因**（`WeaponManager.fire_extinguisher`）：`base_ang = randf() * TAU`，然后按 `base_ang + TAU * i / count` 均分。count = 2 时就是 `base_ang` 与 `base_ang + π` —— 数学上必然是 180°，而 `base_ang` 是纯随机，所以"朝向最近的谁"这件事从来没被读取过。

**改法**：每发各自朝一个最近目标飞。

- 新增 `EnemyPool.nearest_n(from, n, max_dist, out)`：取最近 n 个、按距离升序。用插入排序而非全量 sort —— 同屏 300 只时 n 只有 2~3，`O(n·m)` 远小于排序开销。
- 搜索半径 = `bullet_speed × 1.9 + scatter_radius`（弹体寿命 × 速度 + 溅射），再远的敌人打不到，锁定它等于让这一发白飞。
- 场上不足 count 只时，多余弹体以**平均方向为轴、按 18° 逐级交替左右**补足（±18°、±36°…）。不重新随机 —— 同一次开火的两发不能指向无关方向。
- 零敌人时才退回均分。**数量契约不变**：卡面与 `total_dps()` 都按 `count` 算，所以永远发够 count 颗。

**验收**：`V5InGame` 新增 `[13b]` 共 8 条（157 → **165**）。钉死的数：

| 场景 | 期望 | 实测 |
|---|---|---|
| 单敌人在正东 | 全部偏角 < 40°（不该有朝西的） | 最大偏角 **18.0°** |
| 一东一北 | 两发夹角 ≈ 90°（旧实现恒 180°） | **90.0°** |
| 零敌人 | 仍发 count 颗 | 2 发 |
| 敌人 1320px（超可达） | 不锁定它 | 无发朝它 |

截图对照：`shots/v71_aim_2targets.png`（一东一北，两发分飞）/ `shots/v71_aim_1target.png`（单目标，18° 小扇形）。复现：`V71Shot.tscn -- shot=aim`。

**顺带**：截图工具要手动推 `weapons.update_bullets(0.18)` —— `set_process(false)` 之后弹体不会自己动，不推的话两发都叠在脚下、看不出方向。
