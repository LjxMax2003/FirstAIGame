## 0. 摘要：三个最值得做的

| 优先级 | 方向 | 一句话理由 | 改动量 |
|---|---|---|---|
| **P0** | 打铁花 → **引爆型**（命中即炸 + 范围二段伤） | 现状它只是"穿透 4 个的直线弹"，和它的名字（漫天铁花）完全不匹配；改完就有了唯一的"群体引爆"定位 | 小（`WeaponManager` 一个分支 + 复用已有 shader） |
| **P1** | 商场 **面具架**（12 面，单槽穿戴） | 局外目前只有 5 条线性数值线，玩家没有"构筑选择"；面具提供**有代价的选择**，且傩面是本作的核心题材符号 | 中（`MetaSave` + `ShopUI` 各加一段，不动局内管线） |
| **P2** | 光环 / 打铁花的**触发互斥** | 检索到的真实教训：远程武器会在敌人碰到贴身武器前就把它杀掉，导致贴身武器"看起来装了但没输出" | 小（改判定优先级，不改数值） |

### 0.1 与既有 v4 策划案的关系（先读这段，避免重复劳动）

`docs/design/skills-and-midgame-v4.md` 已经规划了**新武器**（铜锣 / 墨斗 / 木版年画）、**新被动**（回春 / 结界）、**新进化**（开市锣 / 龙筋墨线）、以及**中期难度机制**（浆壳兵 + 更鼓）。

所以本方案**刻意不做三件事**：

1. **不再加新武器**——v4 加完是 9 把可选、6 个槽位，池子已经够；再加只会稀释出场率（详见 §5）。
2. **不碰中期难度**——浆壳兵/更鼓已由 v4 覆盖。
3. **不重复提数值表**——v4 说"数值以 `v4_model.py` 为唯一真相源"，本方案的所有数字都是**方向性验算**，落地必须回填模型。

本方案补的是 v4 没覆盖的三块：**① 打铁花的二次伤害 ② 局外的构筑选择（面具）③ 武器之间的互相干扰**。

## 1. 现状基线（读代码得出的事实，不是猜测）

| 项 | 值 | 出处 |
|---|---|---|
| 武器数 / 满级 | **6（v4 规划后 9）** / 8 | `WeaponDB.MAX_LEVEL`、`skills-and-midgame-v4.md` |
| 武器槽 | 6 | `UpgradeDB.WEAPON_SLOTS` |
| 进化 | 3 条（鞭/糖画/花灯），在原武器上打标记 | `EvolutionDB.FORMS` |
| 局内被动 | 7 条，0~5 级，纯乘数 | `Stats.STAT_KEYS` |
| 局外成长 | 5 条线性线（伤害/生命/冷却/拾取/复活） | `MetaSave.TRACKS` |
| 局外数值硬约束 | meta 满级总乘数 **1.35**，必须明显低于单把武器进化 2.4 | `MetaSave.gd` 头注释 |
| 已有特效 | 12 个 canvas_item shader（含 `cast_burst` 冲击环）；`WeaponManager.spawn_spark()` 火花粒子 | `fx_manifest.json`、`WeaponManager.gd` |

### 1.1 打铁花现在到底怎么打的

`WeaponManager.fire_extinguisher()` → `Bullet{pierce=9999, hit_cap=4}`

```gdscript
# update_bullets() 第 390 行附近
if b.hit_cap > 0:
    b.hit_cap -= 1
    if b.hit_cap <= 0:
        dead = true      # ← 命中第 4 个时直接销毁，没有任何爆炸
        break
```

**关键结论：`hit_cap` 耗尽只是"静默消失"，`spawn_spark(b.pos, 0.7)` 是所有弹道共用的那一点点火星。** 所以你说的"二次范围伤害"现在是 0，不是"不够强"。

### 1.2 光环与远程的抢击杀风险

`fire_halo()` 是贴身 70px 的接触判定（`halo.radius`），`extinguisher` 射程 320。检索到的 VS 案例原话：

> "Phieraggi will typically kill enemies before they ever reach the barrier created by the Garlic."

本作同理：后期打铁花在人堆里穿透清场，光环永远等不到"敌人走进来"，玩家会觉得"花灯是不是坏了"。这条要在改爆炸**同时**处理，否则爆炸会让它更严重。

## 2. 方向一：打铁花 → 引爆型（P0）

### 2.1 设计意图

从 **「直线穿透」** 改成 **「抛出去，砸中人堆，炸开」**。

题材上也更对：打铁花是铁水泼上城墙**撞出漫天火星**，是"接触即爆"，不是"穿糖葫芦"。现在这个"穿透所有目标"的 desc 反而是从别的武器抄来的手感。

### 2.2 机制定义（照抄 Brotato 的成熟规则，含防重复结算）

Brotato 的爆炸有三条规则值得直接采用（来源见 §8）：

1. 爆炸伤害 = 该武器一次正常命中的伤害（不是凭空多一份）
2. **被直接命中的那个敌人，不吃自己触发的那次爆炸**（防双算）
3. 爆炸吃独立的「爆炸伤害 / 爆炸范围」加成

本作落地口径：

```
弹体飞行
  └─ 命中第 1 个敌人
       ├─ 该敌人吃「主伤害」（一次）
       ├─ 以该敌人为圆心，半径 R 内所有**其他**敌人吃「爆炸伤害」
       │    └─ 不含被直接命中的那个（规则 2）
       └─ 引爆标记置位：本发子弹不再引爆（防同一群怪被反复炸）
  └─ 后续命中：只吃主伤害，纯穿透（保留 hit_cap = 4 的原有手感）
```

**「每发只引爆一次」是硬规则**，不是偷懒。若允许每次穿透都引爆，一颗子弹穿过 4 个怪会炸 4 轮，同一群怪被反复炸：

| 打法（场景 C：6 个扎堆，两发） | 总伤 | 相对现状 |
|---|---|---|
| 现状（无爆炸） | 128 | — |
| 每发只引爆一次（推荐） | 188 | +47% |
| 每次穿透都引爆（错误做法） | ≈341 | **+166%** |

所以这条规则不是优化，是**必须**。

### 2.3 代码接入点

`WeaponManager.gd` 的 `update_bullets()`，在 `e.take_damage(b.dmg)` 之后插入：

```gdscript
# update_bullets()，命中分支内
b.hit_ids.append(e.get_instance_id())
e.take_damage(b.dmg)
spawn_spark(b.pos, 0.7)

# ★ 新增：引爆型弹道，命中第一个敌人时炸一次
if b.explode_radius > 0.0 and not b.exploded:
    b.exploded = true
    _explode(b.pos, b.explode_radius, b.explode_dmg, e)   # e = 触发者，排除
```

`Bullet` 类加三个字段：

```gdscript
var explode_radius := 0.0
var explode_dmg := 0.0
var exploded := false
```

新增 `_explode()`（几十行，遍历 `_pool.active`，模式与 `fire_halo()` 的距离判定一致）：

```gdscript
func _explode(pos: Vector2, radius: float, dmg: float, exclude: Enemy) -> void:
    for e in _pool.active:
        if not e.alive or e == exclude:      # ← 规则 2：触发者不吃自己的爆炸
            continue
        if pos.distance_to(e.global_position) < e.hit_radius() + radius:
            e.take_damage(dmg)
    # 可破坏物也吃爆炸（和 try_hit 的口径一致）
    if resources != null:
        resources.try_hit(pos, radius, dmg)
    # 资源点之外的表现：复用已有特效，不新做
    ShaderFX.burst(self, Vector2(radius * 2.0, radius * 2.0),
        Color(1.0, 0.72, 0.35), Vector2.ONE, 10, false, 0.24)
```

**特效零新增成本**：`cast_burst` 就是上一轮做的"发动冲击环"，`rays=10` 正好是"铁花炸开"的径向光条。配合 `spawn_spark` 一次多打几颗即可。

`fire_extinguisher()` 里补：

```gdscript
b.explode_radius = float(d.get("explode_radius", 0.0)) * stat("area")   # 吃范围被动
b.explode_dmg = dmg * float(d.get("explode_ratio", 0.0))
```

`WeaponDB.DEFS.extinguisher` 加两个字段（推荐首版值）：

```gdscript
"explode_radius": 76.0,
"explode_ratio": 0.65,
```

> `explode_radius` 乘 `stat("area")` 是必须的——否则"火候"被动对打铁花只影响飞行距离，玩家点了加范围却发现爆炸没变大，这是最典型的"数值写了但玩家感觉不到"。

### 2.4 数值重分配（关键：这是换形状，不是加伤害）

只加爆炸不改主伤 = 白送 DPS。所以主伤要往下调。

**参考值：`damage` 16 → 13，`dmg_per_level` 2.0 保持**（Lv8 从 30 → 27）。

> ⚠️ **这组数字不能直接拍。** `skills-and-midgame-v4.md` 明确规定"数值以 `v4_model.py` 为唯一真相源"，而 v4 的收敛带里打铁花是「Lv8 总 138 / 单体 17 / 命中 8.0」。改了主伤与爆炸就必须**回填模型重跑九把武器的收敛带**，确认它仍在 96–157 区间内、且不和 `print`（木版年画，同为延迟落点 AoE）撞位。下表是我按 13 手算的验算，只用于说明"换形状"的方向对不对，不作为最终数值。

验算（Lv1，`damage=13`，`count=2`，`hit_cap=4`，爆炸 8.45、半径 76）：

| 场景 | 现状总伤 | 改后总伤 | 变化 |
|---|---|---|---|
| A. 1 个孤立敌人 | 32 | 26 | **-19%** |
| B. 3 个紧邻 | 96 | 112 | +16% |
| C. 6 个扎堆 | 128 | 188 | **+47%** |

算例（场景 C，单发）：
- 命中第 1 个：主伤 13 + 炸到 5 个 × 8.45 = **55.25**
- 后续穿透 3 个：3 × 13 = **39**
- 单发合计 94.25，两发 **188.5**

**这个表就是设计意图本身**：单挑弱一点（打铁花不该是单体最优解），人堆里显著变强（这才是它的定位）。射程 320 + 冷却 1.6s 仍然是它的短板，不会被这一改动抹掉。

> 口径说明：上表是「一次开火（2 发）的理论总伤害」，不是 DPS。v4 表格里的 19 / 138 是每秒伤害，两者不能直接比。这里用"总伤害"是因为要看单次开火的分配形状。

**验收红线**（写进 `SmokeTest`）：
1. 孤立目标伤害不低于现状的 80%
2. 5 目标以上场景提升落在 30%~50% 区间
3. `P5Perf` 60fps 前沿不回退（400 只）

> 注意：这会动到既有的武器数值断言。`SmokeTest` 里如果硬编了 `damage == 16`，需要同步改；建议借这次把武器数值断言改成"读 `WeaponDB` 再算"，避免以后每调一次数值就红一片。

### 2.5 进化形态（如果这条线通过）

现有 3 条进化没有打铁花。若要做，`EvolutionDB.FORMS` 加：

```gdscript
"evolve_extinguisher": {
    "name": "百子千花",
    "base": "extinguisher",
    "req_passive": "area",
    "dps_mult": 1.5,
    "area_mult": 1.4,
    "desc": "打铁花满级 + 火候",
}
```

进化后不止是倍率，建议加一个**行为变化**：`hit_cap` 4 → 无敌，且**每 2 个命中引爆一次**（而不是每发一次）。这样它从"泼一片"变成"在怪潮里连环炸"，是质变而非量变——符合项目既有进化"在原武器上打标记 + 质变"的设计。

> 但要守住 `EvolutionDB` 头注释那条硬约束：进化后 DPS 必须仍低于 6 把武器之和，否则"少拿武器去进化"会变成最优解。

## 3. 方向二：商场面具架（P1）

### 3.1 为什么是面具（题材上这是白送的）

傩戏里有一句现成的话，可以直接当设计口号：

> **「摘下脸壳就是人，戴起脸壳就是神。」**

而且傩面具的分类是**现成的四档**，不需要自己编：

| 傩面原型 | 造型特征 | 天然对应的增益方向 |
|---|---|---|
| **正神** | 慈眉善目、宽脸长耳、面带微笑 | 稳：经验、拾取、续航 |
| **凶神** | 暴眼圆睁、线条粗犷、令人生畏 | 攻：伤害、范围、破防 |
| **世俗** | 接近生活、忠厚朴实 | 经济与生存：金币、减伤 |
| **丑角** | 嘴眼歪斜、滑稽怪诞 | **高风险高回报**：越乱越强 |

颜色也有现成规矩可以借（惠水傩面）：**白脸油滑、红脸忠勇、黑脸正直**。这比"三档颜色"随便挑要站得住。

还有一句可以直接做成收集目标：湘西傩堂戏「**全堂二十四面，半堂十二面**」。首版就做 **12 面**，名字叫"半堂"，收集齐了开"全堂"。

### 3.1.1 一个白送的叙事对照

工程里已有的精英怪叫 **`faceless_nuo_elite`——"无面傩面精英"**。

这个"无面"和玩家的"戴面具"正好构成一组对照：

> 敌人是**摘掉了面具**的残壳（没有神性的空脸）；
> 玩家是**借来面具**的守艺人（戴上是神，摘下是人）。

不需要额外写一句剧情，玩家看到自己戴着唐氏太婆、对面站着一个没有脸的东西，叙事就成立了。这条建议写进面具架的 UI 空状态文案。

### 3.2 机制定义

```
面具架（商店新增一区）
  ├─ 12 张面具，分 4 类（正神 4 / 凶神 4 / 世俗 2 / 丑角 2）
  ├─ 用金币"请"（买下），买过就永久持有
  ├─ 只能戴 1 张 ← 单槽位，这是"选择"的全部来源
  └─ 每张面具 = 1 条增益 + 1 条代价（无代价的选择等于没有选择）
```

**为什么必须单槽位**：多槽位会叠乘，12 张里最优的 3 张会变成"永远的标准答案"，反而不如不做。单槽位 + 代价，才有"这局我想赌一把"的空间。

**为什么必须有代价**：局外商店现有 5 条线是纯增益（花了钱一定变强）。面具如果也纯增益，就是第 6 条线性线，没有构筑意义。代价让"戴哪张"取决于你打算怎么玩。

### 3.3 12 张面具（首版建议）

全部使用检索到的**真实傩面角色名**，不自己编。

| # | 面具 | 原型 | 增益 | 代价 |

设计说明（这几张是重点）：

- **#11 歪嘴秦童**是"丑角"的精髓。检索到的文化解读里，秦童"丑陋卑微却古道热肠、有不凡能力"，正是"低到尘埃里却有神性"。做成"残血增伤"比单纯 +伤害更贴角色。
- **#7 勾簿判官**：判官在傩戏里"勾簿"定生死，做成"击杀刷新冷却"是叙事与机制对上了。
- **#10 指路樵夫**：樵夫"指路"，做成"开局多一张卡"——它是唯一一张改变**开局结构**而不是数值的面具，所以代价用金币。
- **#12 琴童**的随机性让它不适合当主力，但适合"我不知道玩什么"时选，符合丑角的娱乐定位。

### 3.4 代码接入点（尽量不动局内管线）

当前管线是：`Stats.effective_at() = value_at() × MetaSave.mult()`。

面具的数值型增益**直接接进 `MetaSave.mult()` 即可**，一行都不用改 `Stats`：

```gdscript
# MetaSave.gd
var worn_mask: String = ""          # 当前穿戴，存档字段
var unlocked_masks: Array = []      # 已请到的面具

## 面具对某条数值线的乘数（没有面具 / 面具不涉及该线时返回 1.0）
func mask_mult(id: String) -> float:
    var m: Dictionary = MASK_DEFS.get(worn_mask, {})
    var table: Dictionary = m.get("mult", {})
    return float(table.get(id, 1.0))
```

然后在 `mult()` 的返回值上乘一次。

**⚠️ 这里有个必须注意的陷阱**：`MetaSave.mult()` 现有的第一行是

```gdscript
var t: Dictionary = track(id)
if t.is_empty():
    return 1.0          # ← 没有这条成长线就提前返回
```

而 `TRACKS` 只有 damage / max_hp / cooldown / magnet / revive 五条。**`speed`、`area`、`might` 都在 `Stats` 里，但不在 `MetaSave.TRACKS` 里**——所以如果只在最后一行乘 `mask_mult`，那些"没 track 的线"会从 `is_empty()` 直接返回 1.0，面具给的速度 / 范围 / 减伤加成会被静默吞掉。

正确改法（两个 return 都要乘）：

```gdscript
func mult(id: String) -> float:
    var t: Dictionary = track(id)
    if t.is_empty():
        return mask_mult(id)                        # ← 补这里
    var step: float = float(t.get("step", 0.0))
    var lv: int = level_of(id)
    match id:
        "cooldown":
            return (1.0 - step * float(lv)) * mask_mult(id)   # ← 和这里
        "revive":
            return 1.0                              # 复活是次数，不吃乘数
        _:
            return (1.0 + step * float(lv)) * mask_mult(id)
```

**这个陷阱的后果是"改了但没效果"，且不报错**——最难查的那类 bug。建议给 `mask_mult` 加一条断言测试：给一个不改任何 track 的面具（例如只加 `speed`），断言 `Stats.make_base()["speed"]` 真的变大了。

**这一处的连锁效果很关键**：因为 `Stats.make_base()` 和 `apply_to()` 都走 `effective_at()`，改完 `mult()` 之后，面具会**自动**对所有被动等级、所有武器、开局基线生效，不需要在 `WeaponManager` 里加任何分支。这是现有架构本来就设计好的第二乘区，面具只是它的第二个用户。

**例外：非数值型面具**（#7 刷新冷却、#8 反弹、#10 多一张卡、#11 残血增伤、#12 随机被动）走不了乘数管线，需要各自挂点：

| 面具 | 挂点 |
|---|---|
| #7 勾簿判官 | `Enemy._die()` 里回调 `WeaponManager`，**注意别在死亡循环里遍历武器**，用一个 `Game` 层的事件 |
| #8 红牯牛 | `Player.take_damage()` 里反弹，需拿到来源 `Enemy` 引用 |
| #10 指路樵夫 | `UpgradeDB.CARD_COUNT` 改成开局读一次（**不要每帧读**） |
| #11 歪嘴秦童 | `WeaponManager.stat("damage")` 里判断 `hp / max_hp < 0.35` |
| #12 琴童 | `Game` 里一个计时器，随机挑一条 `Stats` key 临时加 Lv |

**建议首版从这 6 张纯数值面具里挑 4 张**（#1 唐氏太婆 / #2 先锋小姐 / #3 黄梁土地 / #5 开山猛将 / #6 开路将军 / #9 黑脸铁匠），先把 `MASK_DEFS` 的 `mult` 字段跑通、存档读通、UI 通了，再逐张加非数值的。一次上 12 张会同时踩"存档兼容"和"局内挂点"两个坑。

> 挑的时候建议覆盖三类：一张加攻击（#5）、一张加经济（#9）、一张加移动（#2）、一张加拾取（#3）。四张都是纯数值，都能走 `mask_mult` 一条路径，但**玩家能明显感觉到"换了张脸打法变了"**——这才验证了系统是否成立。

### 3.5 存档兼容（必读，这是最容易翻车的地方）

`MetaSave.SAVE_VER := 1`。加面具必须升到 2，并且**旧档要能读**：

```gdscript
# load_save() 里
if int(data.get("ver", 1)) < 2:
    worn_mask = ""
    unlocked_masks = []
    # 关键：不要清空 coins / levels，只补新字段
```

另外 `MetaSave` 头注释那条硬约束要**继续守**：meta 总乘数上限 1.35。加面具后最坏情况是 `1.35 × 1.12 = 1.51`，仍然明显低于进化 2.4，安全。但如果以后有人把面具做成 +30%，这条约束就破了——所以建议加一条**测试**（不是运行时 `assert`，Godot 的 `assert` 在 release 构建会被剥掉）：

```gdscript
# SmokeTest 里，而不是 MetaSave 里
func test_mask_gain_bounded() -> void:
    # 面具最大单项增益 × meta 满级，不得超过进化倍率的一半
    _check(_max_mask_gain() * 1.35 < 2.4 * 0.5,
        "面具增益总和过大，会盖过'局内 Build'主玩法")
```

`_max_mask_gain()` 需要自己写：遍历 `MASK_DEFS` 取 `mult` 表里的最大值。

### 3.6 「开光」：一个可选的二段目标（P2，先不做）

检索到：傩面具新刻必须"开光"才附神性，否则只是块木头。

可以做成：买下后是**素面**（灰的、无增益），需要在局内达成条件才"开光"变彩：

- 唐氏太婆：累计拾取 5000 灯花
- 开山猛将：用打铁花击杀 500
- 歪嘴秦童：触发残血增伤 100 次

好处是给了局外一个非数值的长线目标；坏处是"买了用不了"会让玩家不爽。**建议放到收集系统做完之后再考虑，不要和首版一起上。**

## 4. 方向三：其余武器的优化（P2，一句话一条）

| 武器 | 问题（读代码得出） | 建议 |
|---|---|---|
| **花灯 halo** | 与远程抢击杀（§1.2）；`slow_pct 0.15` 太弱，读不出来 | ① 判定优先级：贴身光环对**已经处于减速**的敌人加伤 20%（奖励"把怪留在圈里"）② 减速从 0.15 提到 0.22 |
| **糖画 glowstick** | `pierce 1` 意味着打两个就停，和"拉丝穿透"的 desc 不符 | Lv4 / Lv8 各 +1 穿透（作为等级里程碑，而不是线性给） |
| **皮影 phone** | 环绕体撞到就伤，但**没有击退**，玩家看不出"撞" | 命中时给 0.15 的击退（不是推开，是"顿一下"），比加伤害更能读出"皮影武将撞人" |
| **剪纸 blade** | `bounce 3`，弹射距离 260 固定 | 弹射距离随 `area` 缩放；连续弹同一个目标 2 次以上时第二跳伤害 -30%（防"两只怪互弹到死"） |
| **傩面·师刀 whip** | `length_cap 260` 是硬帽，Lv8 就到顶，后面 4 级几乎无感 | Lv7/Lv8 改成"扫两次"（分两段、各 60% 伤害），用**次数**代替**长度**成长 |

其中「师刀 Lv7/8 扫两次」值得单独说：现在 `length` 每级 +12，Lv8 = 110+84 = 194，但 `length_cap 260` 还没到，所以 Lv8 是长度最大。问题在于**长度是线性收益，玩家感觉不到"变强了"**。改成两次扫击后，视觉上是"挥出两刀"，感知强度远大于 +12px。

## 5. 方向四：新技能 —— 本方案**不建议**再加

### 5.1 先说结论：新武器池已经够满了

本工程已有 `docs/design/skills-and-midgame-v4.md`，它已经规划了 **3 把新武器**：

| id | 名 | 型 | 定位 |
|---|---|---|---|
| `gong` | 铜锣 | aura / AoE | 光环对位 |
| `inkline` | 墨斗 | line / 单点 | **破壳核心**（对浆壳兵 ×1.80） |
| `print` | 木版年画 | zone / AoE | 延迟落点爆发 |

加上现有 6 把 = **可选池 9 把，而武器槽只有 6 个**（`UpgradeDB.WEAPON_SLOTS`）。

这个比例是健康的：9 选 6 意味着每局必然放弃 3 把，构筑有取舍。**再加武器只会稀释每一把的出场率，不会增加决策深度。**

所以本方案不重复提新武器。真正缺的不是"更多武器"，是**现有武器的表达深度**（§4）和**局外构筑选择**（§3）。

### 5.2 我原本考虑过、但不建议现在做的 4 个

留作 v5 备选，等 v4 的 9 把跑过真机 A/B 再评估：

| 候选 | 题材依据 | 机制 | 为什么先不做 |
|---|---|---|---|
| 皮影戏台 | 皮影 | 脚下插"戏台"区域，延迟 2s 跟随玩家 | 和 v4 的 `print`（延迟落点 zone）职责重叠 |
| 扎染 | 扎染（非遗） | 命中留"染斑"，染斑之间连线 | 唯一改动可控的候选，但要等 v4 槽位压力实测 |
| 木活字 | 木活字印刷（非遗） | 攒 N 个"字块"后全屏一次"印" | 与现有全自动武器心智冲突，需要额外 UI |
| 傩面替身 | 傩仪方相氏驱疫 | **主动技**：咆哮推开全屏 + 大伤害，CD 45s | 本作**没有主动技**，这是最大机制缺口，但要动输入与 UI，和竖屏单摇杆模型冲突，风险最高 |

> 最后一条值得单独记住：**"没有主动技"是本作真正的机制缺口**，比"缺一把武器"重要得多。但它属于另一个量级的改动（输入 / UI / 平衡全要动），不该混在这次里做。

## 6. 落地顺序与风险

### 6.1 建议顺序

```
第 1 步  打铁花爆炸（§2）
         ├─ 只动 WeaponManager + WeaponDB 两个文件
         ├─ 复用 cast_burst，零新增美术
         └─ 验收：3 场景伤害表 + P5Perf 不回退 + v4 模型收敛带
         ↓
第 2 步  光环/远程互斥（§4 第 1 条）
         └─ 和第 1 步同一批改，因为爆炸会加剧抢击杀
         ↓
第 3 步  面具架 —— 先做 4 张纯数值面具（§3.4）
         ├─ 跑通 MASK_DEFS / 存档 v2 / ShopUI 一区
         └─ 验收：旧档能读、买-戴-卸 状态正确、乘区叠加不破 1.51
         ↓
第 4 步  补齐 12 面 + 非数值面具
         ↓
第 5 步  其余武器微调（§4 表格）
         └─ 放在 v4 的 3 把新武器落地之后做，避免同时改 9 把的数值
```

### 6.2 风险清单

| 风险 | 具体表现 | 规避 |
|---|---|---|
| **爆炸导致漏节点** | 每次命中都 `ShaderFX.burst()` 会瞬间生成大量 ColorRect | 每发只引爆一次（§2.2 硬规则）；`burst()` 内部已有 `queue_free` |
| **面具让旧档崩溃** | 加字段没升 `SAVE_VER`，旧档读出来 `worn_mask` 为 null | 升 ver + 逐字段 `get(默认值)` |
| **面具在局内改乘数** | 局内换面具导致 `Stats` 已写入的值和乘数不一致 | 面具**只能在商店改**，进局后锁定；`Game` 开局读一次 |
| **数值断言大面积红** | `SmokeTest` 硬编了武器伤害 | 借这次把断言改成"读表再算" |
| **单槽位没有选择感** | 12 张里只有 1 张明显最优 | 每张必须有真实代价；建议先做 4 张可用性测试 |

### 6.3 一条总原则

检索到的 VS 反面案例值得抄成项目红线：

> 武器之间会互相吃掉触发条件。远程清场 → 贴身武器空转。

**任何"增强单把武器"的改动，都要问一句：它会不会让另一把武器变成摆设。** 打铁花爆炸后会更强地抢走光环的怪，所以这两条必须同批改，不能只做一半。

## 7. 与既有系统的衔接检查

| 检查项 | 结论 |
|---|---|
| 面具会破坏 `Stats` 纯公式吗？ | 不会。`value_at()` 保持纯净，面具走 `meta_mult()` 第二乘区 |
| 打铁花改动会碰进化约束吗？ | 若不加进化，不影响。若要加（§2.5），需复算 `EvolutionDB` 的 DPS 上界 |
| 会撞 v4 的新武器规划吗？ | **会有一处隐患**：打铁花改成引爆型后，与 v4 的 `print`（木版年画，延迟落点 AoE）职责接近。建议把两者拉开——`print` 走"定点延迟大爆发"，打铁花走"移动中即时小爆炸"，并在 v4 模型里确认两者不互相替代 |
| §4 的武器微调会破坏 v4 收敛带吗？ | **会**。任何 `damage` / `pierce` / `radius` 改动都要回填 `v4_model.py` 重跑九把武器的 96–157 收敛带 |
| 会新增 shader 吗？ | 不需要。`cast_burst` + `spawn_spark` 已够用 |
| 需要新美术吗？ | **面具需要 12 张新图标**。查过 `Art.gd`，现有只有 `faceless_nuo_elite`（无面傩面精英）和 `nuo_blade_arc`（傩面师刀弧光），都不是可用的面具图标。建议先用纯色块 + 面具名文字占位跑通逻辑，美术最后补 |
| 存档格式变化 | `SAVE_VER` 1 → 2 |

### 7.1 建议同步做的一件事

本方案的三个方向都会碰到"改了数值但没人验证"的问题。建议顺手加一个**武器数值快照测试**：

```gdscript
# SmokeTest 里：不硬编任何数字，而是把当前 9 把武器的 Lv1/Lv8 总 DPS 打成一张表，
# 与 v4 的五条收敛带区间比对，超界就红。
```

这样以后任何人调武器数值，都会立刻看到"这把跑出收敛带了"，而不是等玩家反馈。
