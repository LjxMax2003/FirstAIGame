# 缺陷报告：铜铃全图吸取 + 玩家移动导致经验宝石"逃逸式漂浮"

> 测试类型：**功能测试（Functional Test）**
> 被测模块：`GemPool` / `Gem`（经验宝石） + `PickupField`（铜铃＝磁铁，全图吸取经验）
> 引擎版本：Godot 4（本机可用 4.6；工程已用 4.7.2 验证）
> 复现率：**100%**（确定性用例，非概率）
> 严重度：**中**（不影响数值正确性，但明显破坏拾取手感与"全图秒吸"的可用性）
> 关联用例：`res://tests/func_magnet_vacuum_move_float/FuncMagnetVacuumMoveFloat.tscn`

---

## 1. 现象（用户侧）

拾取「铜铃」（磁铁，一次性吸取全场经验宝石）的瞬间，如果玩家在移动，
会出现**部分经验宝石在场上漂浮一段时间**才被收进袋，极端时长时间不收。
静止不动时则一切正常、全图瞬间清空。

## 2. 复现条件

- 触发：拾取「铜铃」→ `GemPool.vacuum_all()` 对全场宝石置 `forced = true`
- 必要条件：**玩家在吸取期间持续移动**
- 范围：仅**临界半径（约 465px）以外**的远处宝石会浮，近处宝石照常被收
  → 表现为"部分漂浮"，与用户描述一致

## 3. 根因（已定位，供修复参考）

`Gem.tick()` 的强制吸取走的是**惯性吸附**，而非直接朝玩家修正位置：

```gdscript
# Gem.tick()，forced 状态下
var d = to_player.length()
var pull = FLIGHT_ACCEL if d < PULL_RADIUS else FLIGHT_ACCEL * 0.4   # 远处仅 2600
vel += to_player / d * pull * delta
vel = vel.limit_length(MAX_FLIGHT_SPEED)        # 1100 px/s
```

- 玩家移动会给远处宝石注入**切向速度分量**。
- 维持贴身绕飞所需的向心加速度约 `V_c² / R`（V_c = 1100）。
- 当 `R > ~465px` 且 `pull(2600) < V_c² / R` 时，吸附力拉不回宝石，
  宝石**螺旋向外逃逸** → 视觉上"漂浮"。
- 静止时宝石是纯径向冲入（无切向分量），所以只在移动时复现。

一句话：**吸附是"加速度累加"模型，远程拉力不足 + 玩家移动注入切向速度 =
远处宝石离心逃逸**。

## 4. 预期 vs 实际

| 项 | 预期（正确行为） | 实际（缺陷） |
|---|---|---|
| 铜铃全图吸取（静止） | 窗口内清空，耗时 ≤ 1.5s | ✅ 正常 |
| 铜铃全图吸取（移动） | 窗口内清空，耗时 ≤ 1.5s | ❌ 远处宝石残留/漂浮，耗时超 1.5s |
| 是否"仅移动时出现" | 与移动无关 | 仅移动时复现 —— 与用户反馈一致 |

## 5. 修复建议（方向，非必须）

任选其一即可消除漂浮：

1. **直瞄修正（推荐）**：`forced` 状态下让 `vel` 直接朝玩家插值/限速对齐，
   而非纯累加加速度，彻底消除切向逃逸。
2. **提升远程拉力**：把 `FLIGHT_ACCEL * 0.4` 的远处档调高，使 `pull ≥ V_c²/R_max`
   （R_max 取场上宝石最远分布），保证任何半径都能拉回。
3. **移动时把宝石锚定朝玩家**：`forced` 期间以玩家实时位置为吸附目标，
   玩家移动时目标同步跟随，宝石不会"追丢"。

> 注：单位换算与临界半径 465px 来自 `MAX_FLIGHT_SPEED=1100` 与 `FLIGHT_ACCEL=2600`
> 的粗略估算，具体阈值以真机为准；方向 1 最稳。

## 6. 验证用例（如何跑通）

确定性功能测试，两条阶段：

- **阶段 A（对照，静止）**：玩家四周铺 16 颗宝石（300px / 600px 两档 × 8 方向），
  脚下生成铜铃走真实拾取通路触发 `vacuum_all`，断言窗口内清空。
- **阶段 B（复现，移动）**：同样铺宝石 + 拾取铜铃的同一刻让玩家持续移动，
  断言全图也应清空且耗时 ≤ 1.5s；否则记为"漂浮一段时间"（复现缺陷）。

## 7. 影响范围

- 仅影响「铜铃」这类一次性全图吸取道具在**玩家移动**时的表现。
- 普通磁吸半径内拾取、静止吸取均不受影响。
- 不造成数值错算或崩溃，属于手感/可用性缺陷。

## 8. 修复记录（2026-10-30，Godot 4.7.2 stable headless）

### 8.1 修复前的现场复现（本机 4.7.2 实测）

```
[功能·对照] 铜铃全图吸取 + 玩家静止
  ok   静止时铜铃在 0.87s 内把全图宝石收进袋（剩 0 颗）
[功能·缺陷复现] 铜铃全图吸取 + 玩家持续移动
  FAIL 移动时铜铃在 4.07s 内把全图宝石收进袋（剩 9 颗 / 最远 231px）
```

与 4.6 的结论一致（4.6 当时是剩 7 颗 / 210px），确认缺陷跨版本存在，非引擎差异。

### 8.2 根因复核

报告 §3 的判断成立，补一条量化依据：玩家移动速度 `Player.BASE_SPEED = 220`，
宝石飞行速度上限 `MAX_FLIGHT_SPEED = 1100`、加速度 `FLIGHT_ACCEL = 2600`。
纯累加模型下速度方向要靠加速度掰回来，可修正半径 `R < v²/a`：

| 场景 | 进场时的速度 | 可修正半径 v²/a | 结果 |
|---|---|---|---|
| 普通磁吸（进圈时就近） | 从 0 起步，到 90px 处约 684 | 180px | 圈内即可收敛 |
| 铜铃全图吸取（600px 外） | 已跑满 1100 | **465px** | 在 465px 处形成绕飞轨道，永不进袋 |

所以"只有铜铃 + 只有移动"复现：静止时宝石是纯径向冲入，没有切向分量需要修正。

### 8.3 采用修复

按报告 §5 的方向 1（直瞄修正），落在 `scripts/Gem.gd` 的 `tick()`：

```gdscript
# 旧：速度纯累加，切向分量只能靠加速度慢慢磨掉
vel += to_player / d * pull * delta
vel = vel.limit_length(MAX_FLIGHT_SPEED)

# 新：把速度投影到**径向**再累加 —— 切向分量当场丢弃
var speed: float = maxf(vel.dot(dir), 0.0) + pull * delta
vel = dir * minf(speed, MAX_FLIGHT_SPEED)
```

选它而不是方向 2（加大远处拉力）的理由：方向 2 只是把临界半径推远，
**换个更远的宝石分布就会复发**（临界半径永远是 v²/a，拉扯越猛 v 也越接近上限）；
投影消除的是"存在切向逃逸轨道"这个性质本身，任何距离、任何玩家速度都不会绕飞。

保留的两处手感没有被改掉：
- 加速度仍然从 0 爬到 1100（约 0.42s），"被拽进去"的窜出感不变；
- `near` 的近距增力仍保留，落袋前那一下仍是加速收束。

附带收益：`vel` 从此恒指向玩家，落袋路径是纯径向，单帧位移一定小于放宽后的
拾取半径（`PICKUP_R × 2 = 44`），原先"高速擦身而过再绕回来"的隐患一并消掉。

### 8.4 修复后验证

```
[功能·对照] 铜铃全图吸取 + 玩家静止
  ok   静止时铜铃在 0.87s 内把全图宝石收进袋（剩 0 颗）
  ok   静止时清空耗时 0.87s ≤ 上限 1.5s
[功能·缺陷复现] 铜铃全图吸取 + 玩家持续移动
  ok   移动时铜铃在 1.08s 内把全图宝石收进袋（剩 0 颗 / 最远 0px）
  ok   移动时清空耗时 1.08s ≤ 上限 1.5s
========== 全部通过 OK ==========
```

退出码 `0`。移动态比静止态慢 0.21s 属预期：玩家在跑，宝石要多追一段。

### 8.5 连带修掉的一处测试污染（非本缺陷，但会让本用例误判）

跑回归时发现 `V5InGame` 有约 1/3 概率随机失败，且每次失败的断言不同
（`墨斗 0.0 伤害` / `糖画实测 14.68 期望 10.00` / `铜锣实测 13.38 期望 8.70`）。
三者差值恒为 **+4.68**，是上一条用例（打铁花）打出去的弹体还在飞，飞进了
下一条用例刚生成的敌人身上。

- `WeaponManager` 新增 `clear_bullets()`（走 `_release_bullet` 回收，不漏池）；
- `V5InGame._reset()` 里连同在飞弹体一起召回。

修后连跑 5 次全部 `157 条断言` 通过。这类污染和宝石无关，但会让任何
"改了 A、B 却红了"的判断失效，所以一并处理。
