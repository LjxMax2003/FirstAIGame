## 二、Step 6：统一数值管线

### 2.1 核心规则

> **被动不直接改武器，武器不直接读被动。所有人只经过 `stats` 这一个字典。**

改动前的旧代码是"每把武器的常量写在 `WeaponManager` 顶部，被动直接在 `UpgradeDB.apply()` 里改这些常量"，
结果是加一把武器要改两处、调一个数值要搜三个文件，而且公式还和设计文档对不上。

### 2.2 唯一公式出口：`scripts/Stats.gd`

| 被动 | 公式 | Lv5 值 | 说明 |
| --- | --- | --- | --- |
| 伤害 `damage` | `1 + 0.10L` | ×1.50 | 直接乘到武器伤害 |
| 冷却 `cooldown` | `max(0.40, 1 − 0.05L)` | ×0.75 | **越大越慢**，是冷却时间倍率 |
| 范围 `area` | `1 + 0.07L` | ×1.35 | 乘到长度/半径/宽度 |
| 移速 `speed` | `1 + 0.08L` | ×1.40 | 乘到玩家基础 220 |
| 磁吸 `magnet` | `1 + 0.25L` | ×2.25 | 乘到基础吸附半径 90 |
| 生命 `max_hp` | `100 + 20L` | 200 | 单独处理，升上限时补血 |
| 力量 `might` | `max(0.50, 1 − 0.07L)` | ×0.65 | 乘到敌人接触伤害 |

**三个修正点**（旧代码与 NUM_DESIGN v3.1 不一致，本次改正）：

1. `cooldown` 旧值用 `1 − 0.08L` → 改为 `1 − 0.05L`
2. `area` 旧值用 `1 + 0.10L` → 改为 `1 + 0.07L`
3. `might` 旧值用 `max(0.30, 1 − 0.08L)` → 改为 `max(0.50, 1 − 0.07L)`

> 地板说明：等级被 `clampi(lv, 0, 5)` 钳在 5，所以 `cooldown` 的 0.40 地板和 `might` 的 0.50 地板
> 在正常游戏内**永远触发不到**（要到 Lv12 / Lv8 才会碰到）。公式里保留地板是防御性写法，
> 不是当前数值的一部分——这一点在测试里也写成了"核对公式下限"而不是"指望 value_at 掉到地板"。

### 2.3 数据流

```
升级三选一
   └→ UpgradeDB.apply()
        ├→ 武器卡：只写 GameManager.weapons.owned[id] = lv
        └→ 被动卡：只写 Stats.apply_to(GameManager.stats, id, lv)
                        ↓
             GameManager.stats（唯一真值）
                        ↓
             WeaponManager 每帧读取（不缓存快照）
```

`apply_to()` 对 `max_hp` 做特殊处理：涨上限时把新增的那部分**直接补进当前血量**，
否则玩家点了"生命上限 +20"会觉得"血条反而更空"。

## 三、Step 7：数据驱动武器定义

### 3.1 从 3 把到 6 把

| id | 名称 | 类型 | 机制 |
| --- | --- | --- | --- |
| `whip` | 鞭弧 | melee | 身前左右交替横扫，矩形判定，长度有上限 |
| `halo` | 光环 | aura | 周期脉冲灼烧贴身敌人 + **减速 15% / 0.6s** |
| `glowstick` | 荧光棒 | projectile | 锁定最近敌人，穿透 1，发数按等级增加 |
| `phone` | 手机环 | orbit | 环绕自身旋转，持续撞击 |
| `blade` | 美工刀 | projectile | 命中后弹射到附近另一个目标（最多 3 次） |
| `extinguisher` | 灭火器 | arc_projectile | 向四周抛出，全穿但每目标只结算一次 |

新增第 4、5、6 把武器**只改了 `WeaponDB.DEFS` 的数据 + `WeaponManager.fire()` 的 dispatch**，
没有在别处散落任何常量。这是 Step 7 的验收口径。

### 3.2 两个必须守住的数值修正

**① 光环：减速而不是推开**

原案写的是"光环把敌人推开"。这在数值上是有毒的设计：被推开的敌人永远进不了接触判定，
等于给玩家一个**无声的永久无敌**。改成"减速 15%，持续 0.6s"之后：

- 压制推进的手感保留了（敌人确实变慢）
- 被围住照样掉血（接触判定不受影响）

测试里专门验了这一条：被减速的敌人位移 < 12px，仍然贴在玩家身边。

**② 荧光棒：`dmg_per_level = 3.0` 是硬性的**

如果按常规的每级 +1.0 涨，Lv8 荧光棒的伤害会低于 Lv1 鞭弧，
玩家升到 8 级反而变弱——这是纯粹的手感灾难。所以这里给了 3.0 的斜率：

```
荧光棒 Lv8 = 12 + 3.0×7 = 33.0
鞭弧   Lv1 = 10.0
```

## 四、Step 8：进化配方

### 4.1 三条配方

| 进化形态 | 基础武器 | 需要武器 | 需要被动 | DPS 倍率 | 范围倍率 |
| --- | --- | --- | --- | --- | --- |
| **血鞭** | `whip` 鞭弧 | Lv8 | `damage` 力量 Lv≥1 | ×1.7 | ×1.5 |
| **圣魔杖** | `glowstick` 荧光棒 | Lv8 | `cooldown` 冷却 Lv≥1 | ×1.5 | ×1.0 |
| **圣蒜** | `halo` 光环 | Lv8 | `area` 范围 Lv≥1 | ×1.4 | ×1.6 |

### 4.2 流程

```
精英敌人死亡（每 38 秒一只）
   └→ 必掉宝箱（Art.CHEST，地上浮动）
        └→ 玩家走进 50px 内自动开箱
             ├→ 满足配方：进化 + 金星特效 + 金色横幅
             └→ 不满足：补偿一次普通升级（不让玩家白捡一个废箱）
```

**宝箱掉率是 100%，不是随机。** 理由：进化的设计意图是"可预期的惊喜"——
玩家应该能规划"我要把鞭弧养到 8 级 + 拿个力量被动然后等宝箱"，
而不是碰运气刷箱子。

### 4.3 进化为什么不占新武器槽

进化不改武器 id，而是在 `WeaponManager.evolved` 里打一个 `{weapon_id: form_id}` 标记，
读数值时把 `dps_mult / area_mult` 乘进去。这样：

- 槽位数不变（6 格还是 6 格）
- HUD 上同一格变成金边 + 显示 `MAX`
- 升级池里不再出现已进化的武器

### 4.4 关键约束：`X11 < X1`

这是整个进化系统最难守的一条：

> 三把进化武器的 DPS/R **必须低于**六把未进化武器之和。

如果不满足，"少拿武器去专心进化"会变成唯一最优解，6 个槽位的设计就废了。
所以倍率被钉死在 1.7 / 1.5 / 1.4 —— 不是"看起来爽的数字"，而是**算出来能过约束的上限**。

自动化验算结果（`_dps_per_radius` 粗算）：

```
六把未进化之和 X1  = 354.7
最强进化单把       = 117.2  < 354.7  通过
六把全进化   X11   = 439.9  < 354.7×3 通过
```

## 七、修掉的两个渲染 bug

这两个都是**阶段二新增内容才暴露出来**的，阶段一测不到：

**① 手机环完全不可见**

`_ensure_orbit_sprites` 用 `add_child` 把精灵挂在 `WeaponManager` 下，
但代码写的是 `s.position = 世界坐标`。管理器自身带父节点变换，
结果手机被整体偏移到玩家视野外。改为 `s.global_position` 后正常。

**② 弹道类武器被敌人遮住**

荧光棒/美工刀/灭火器的精灵默认 `z_index = 0`，和敌人同层，
穿过 40 只敌人时会被完全盖住。改为 `z_index = 3`（敌人之上、特效之下）。
